Internal contract:
- Single asyncio writer (TX_LOCK serializes heartbeat + command-sender producers).
- Single OS reader (RX thread; only place that calls transport.read_line).
- RX thread parses INTO `ProtocolEvent` and bridges to asyncio queue via `loop.call_soon_threadsafe(_enqueue, event)` — `_enqueue` runs on the loop thread, applies drop-oldest semantics on full queue (256-cap).
- Mid-session `Ready` event → recovery state machine:
  1. Set `_dispatch_paused = True`.
  2. Send S: from Config → wait for structured `Settings` ack (NOT `SettingsInfo`) within `arduino_ready_timeout_sec`.
  3. Send L: from Config → wait for `Limits` ack within `arduino_ready_timeout_sec`.
  4. Set `_dispatch_paused = False`. Resume.
  - Heartbeat continues throughout recovery (firmware-watchdog must stay satisfied).
  - Ack timeout → WatchdogResetError, halt.
- `Error` event from firmware → set state = FAULTED, set `_dispatch_paused = True`, surface via the events() stream as `Error` AND via raising `FirmwareErrorReceived` from the next `send_*` call (no auto-recover; CONTEXT.md Out-of-Scope).

    """Asyncio orchestrator for the Arduino stepper firmware (v2).

    Bridges the pure parser (arduino_protocol.py) and the transport
    (arduino_transport.py) into a working motor link. Owns the only
    threading↔asyncio bridge in the project: a daemon RX thread reads
    bytes, parses to ProtocolEvent, then crosses into the asyncio
    loop via loop.call_soon_threadsafe to enqueue a bounded queue.

    Concurrency invariants (CLAUDE.md rule 1, RESEARCH.md "Architecture
    & Concurrency"):
        - Single writer: only the asyncio loop calls transport.write,
          always behind self._tx_lock.
        - Single reader: only the RX daemon thread calls transport.read_line.
        - Bounded RX queue: maxsize=256, drop-oldest + WARN log on full.
        - Mid-session Ready event = MCU watchdog reset → re-issue
          settings + limits from Config → resume.
        - ERROR:N from firmware halts dispatch, requires manual reset
          (CONTEXT.md Out-of-Scope: no auto-recover).
    """

    5. Set `_state = RUNNING`. Log "handshake_complete" with version + elapsed_ms.
    6. Spawn `self._rx_thread = threading.Thread(target=self._rx_loop, name="arduino-rx", daemon=True)`. Start it.

    `def _rx_loop(self) -> None` — runs in the RX thread:
    ```
    while not self._stop_event.is_set():
        try:
            line = self._transport.read_line(_RX_THREAD_READ_TIMEOUT_SEC)
        except Exception as exc:                  # noqa: BLE001 — see below
            # Tiger-style: surface as LinkLostError on the loop thread.
            if self._loop is not None and not self._stop_event.is_set():
                self._loop.call_soon_threadsafe(self._on_link_lost, exc)
            return
        if line is None:
            continue
        try:
            event = parse_line(line)
        except ProtocolParseError as exc:
            self._logger.warning("malformed_line", line=line[:32].decode("ascii", errors="replace"), error=str(exc))
            continue
        # Cross to loop thread:
        if self._loop is not None:
            self._loop.call_soon_threadsafe(self._on_rx_event, event)
    ```
    NB: the `noqa: BLE001` is the SINGLE allowed exception — pyserial.SerialException can come from read_line on USB disconnect, and we MUST translate it to a typed orchestrator-level error rather than crashing the daemon thread. Document this with a code comment "RX thread bridge: serial errors (USB unplug, OS handle close) translate to LinkLostError on the loop thread; never silently swallow".

    `def _on_rx_event(self, event: ProtocolEvent) -> None` — runs on loop thread (called via `call_soon_threadsafe`):
    1. If `event` is `Feedback`, run `_check_seq_gap(event)` (mod-2^32 rollover-safe gap detection per Pitfall 7 — see 02-RESEARCH.md lines 1010-1024 verbatim).
    2. If `event` is `Ready` AND `_state == RUNNING`: log "watchdog_reset_detected", spawn `asyncio.create_task(self._recover())`. Don't enqueue this Ready into the public events queue — it's a control signal, not a payload event.

Log "error_received" with code, code_name (`event.code.name if isinstance(event.code, ErrorCode) else "Unknown"`), message. Then enqueue (so events() consumers see it).
    4. Otherwise enqueue via `_enqueue(event)`.

    `async def _wait_for_event(self, event_type: type, *, timeout: float, stage: str) -> ProtocolEvent`:
    Drains queue until either an event of `event_type` arrives or `timeout` elapses. Discriminate `Settings` (5-tuple) from `SettingsInfo` (textual) — the recovery ack-watcher must wait for the structured `Settings` form per Pitfall in 02-RESEARCH.md lines 504-506. Drain non-matching events back to the queue OR drop (drop is simpler — recovery doesn't care about FB lines arriving meanwhile). Use `asyncio.wait_for(self._rx_queue.get(), timeout=remaining)` in a loop with deadline tracking.

    Implementation: track `deadline = loop.time() + timeout`. In the loop, compute `remaining = deadline - loop.time()`. If <= 0, raise `asyncio.TimeoutError`. Else `ev = await asyncio.wait_for(self._rx_queue.get(), timeout=remaining)`. If `isinstance(ev, event_type)`, return it. Else discard (it's a stale FB or a SettingsInfo while waiting for Settings). Log discarded events at DEBUG level for diagnostics.
