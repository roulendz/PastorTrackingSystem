       class PySerialTransport:
           """Real pyserial wrapper. Single owner of the OS-level serial handle."""
           def __init__(self, port: str, baud: int) -> None:
               self._serial = serial.Serial(port=port, baudrate=baud, timeout=_PYSERIAL_OPEN_TIMEOUT_SEC)

           def write(self, data: bytes) -> int:
               return self._serial.write(data)

           def read_line(self, timeout: float) -> bytes | None:
               # pyserial Serial.timeout is the per-read timeout. Patch it for this call.
               # Only the RX thread calls read_line; this property write is single-threaded
               # by the orchestrator's invariant (Plan 02-03: "single OS reader = the RX
               # daemon thread; never the loop, never the heartbeat task"). Do NOT refactor
               # toward a multi-reader pattern — concurrent writers to self._serial.timeout
               # would race on the OS handle update and corrupt timeout semantics.
               self._serial.timeout = timeout
               line = self._serial.read_until(_DEFAULT_RX_BUF_TERMINATOR)
               if not line.endswith(_DEFAULT_RX_BUF_TERMINATOR):
                   return None       # timed out
               return line.rstrip(b"\r\n")

           def close(self) -> None:
               self._serial.close()
       ```
       Note: `_serial.timeout = timeout` triggers a property write that pyserial uses to update the OS-level handle; this is the documented idiom (RESEARCH line 535-538). Acceptable mypy: pyserial has `serial.*` in mypy overrides (pyproject.toml:80) so `Serial` types are `Any` — to keep `disallow_any_explicit` clean, annotate `self._serial: "serial.Serial"` if mypy complains, or rely on the override silencing the inferred Any.

       class FakeSerialTransport:
           """Bidirectional in-memory fake. Tests feed_rx() to enqueue inbound lines
           (without trailing \\n) and assert against captured_writes."""

           def __init__(self) -> None:
               self.captured_writes: list[bytes] = []
               self._rx_lines: collections.deque[bytes] = collections.deque()
               self._rx_event = threading.Event()
               self._closed = False

           def feed_rx(self, line: bytes) -> None:
               self._rx_lines.append(line)
               self._rx_event.set()

           def write(self, data: bytes) -> int:
               if self._closed:
                   raise FakeSerialClosedError("write on closed FakeSerialTransport")
               self.captured_writes.append(data)
               return len(data)

           def read_line(self, timeout: float) -> bytes | None:
               if self._rx_lines:
                   line = self._rx_lines.popleft()
                   if not self._rx_lines:
                       self._rx_event.clear()
                   return line
               if self._rx_event.wait(timeout):
                   self._rx_event.clear()
                   if self._rx_lines:
                       return self._rx_lines.popleft()
               return None

           def close(self) -> None:
               self._closed = True
               self._rx_event.set()  # unblock any waiter
       ```
       Note: NB the `if not self._rx_lines: self._rx_event.clear()` after popleft fixes a subtle correctness issue not in the RESEARCH sketch — without it, repeated `read_line` calls return immediately (event still set) when queue is empty. Add this; it's the right fix.

       ```
       def discover_arduino_port(configured_port: str | None) -> str:
           """VID:PID auto-detect with manual-override fallback. — IO-ARD-01

           Resolution order:
               1. configured_port if not None AND present in comports() → use it (logs port_manual_override).
               2. configured_port if not None AND absent → ArduinoPortNotFoundError.
               3. configured_port is None → first comports() entry whose (vid, pid)
                  is in SUPPORTED_VID_PIDS:
                  - exactly 1 match → return it; log INFO "port_discovered" with port/vid/pid.
                  - multiple matches → return first; log INFO "port_multiple_matches" with chosen + all list.
               4. None match → ArduinoPortNotFoundError.

           Tiger-style: configured-but-absent raises rather than falling back —
           silent fallback to auto-detect would mask developer/operator misconfig.
           """
           log = structlog.get_logger(module="arduino_transport")
           ports = list(comports())
           if configured_port is not None:
               if any(p.device == configured_port for p in ports):
                   log.info("port_manual_override", port=configured_port)
                   return configured_port
               raise ArduinoPortNotFoundError(
                   f"arduino_port={configured_port!r} not present in serial.tools.list_ports"
               )
           matches = [
               p for p in ports
               if p.vid is not None and p.pid is not None
               and (p.vid, p.pid) in SUPPORTED_VID_PIDS
           ]
           if not matches:
               raise ArduinoPortNotFoundError("no Arduino USB device matched VID:PID set")
           if len(matches) > 1:
               log.info(
                   "port_multiple_matches",
                   chosen=matches[0].device,
                   all=[(m.device, hex(m.vid), hex(m.pid)) for m in matches],
               )
           else:
               log.info(
                   "port_discovered",
                   port=matches[0].device,
                   vid=hex(matches[0].vid),
                   pid=hex(matches[0].pid),
               )
           return matches[0].device
       ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS USB enumeration → `discover_arduino_port` | The set of `(vid, pid)` pairs reported by `serial.tools.list_ports.comports()` is OS-trusted. A hostile USB device matching a supported VID:PID would route through this code. |
| `configured_port` config string → discover_arduino_port | The string from `Config.arduino_port` is operator-set (no remote input), but is still a string we present to the OS. |
| Multi-thread access to `pyserial.Serial` handle | `PySerialTransport.read_line` writes the OS-level `timeout` property; ONLY the RX thread is permitted to call `read_line`. The orchestrator's single-reader invariant (Plan 02-03) is what makes this property write race-free. WARN 4 documents this inline. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | discover_arduino_port — VID:PID match | accept | A hostile USB device matching the documented VID:PID is the operator's problem (RESEARCH.md Security Domain row 3 — "user has bigger problems"). VID:PID set is the gate; we add no second factor. |
| T-02-01b | Tampering / Misconfig | configured_port absent | mitigate | When `configured_port` is non-None and not present in comports(), raise ArduinoPortNotFoundError rather than silently auto-detecting (CONTEXT.md Disconnect & Port Discovery — silent fallback would hide the misconfig). |
| T-02-01c | Information Disclosure | port_multiple_matches log | accept | Log line includes the full list of matching device paths and vid/pid hex. Local USB context, no PII risk; useful for operator triage. |
| T-02-01d | Tampering / Race | concurrent writes to `self._serial.timeout` | mitigate | `PySerialTransport.read_line` is callable only by the RX thread per orchestrator invariant; inline comment in the implementation forbids refactoring toward a multi-reader pattern (WARN 4). |
