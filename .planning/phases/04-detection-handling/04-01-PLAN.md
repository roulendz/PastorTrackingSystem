<objective>
Implement detection state machine with dropout filtering, hold behavior, timeout-triggered home return, and recovery easing in the TrackerController pipeline.

Purpose: Make the camera behave gracefully when detection is lost -- hold position during brief gaps, return home after sustained loss, and ease back into tracking on recovery. This prevents the camera from snapping to home on brief MediaPipe misses and makes recovery feel like a human camera operator re-acquiring the target.

Output: DetectionState enum and state machine in tracker_controller.py, two new config fields in config_manager.py, comprehensive test suite in test_detection_handling.py.
</objective>

<feature>
  <name>Detection State Machine with Dropout Filtering and Recovery Easing</name>
  <files>src/control/tracker_controller.py, src/utilities/config_manager.py, tests/test_detection_handling.py</files>
  <behavior>
    ## Detection Dropout Filtering (DTCT-03)
    - Single dropped frame (bDetected=False for 1 frame, then True): commanded angle does not change during the dropped frame
    - Two consecutive dropped frames: commanded angle does not change during either frame
    - Three consecutive dropped frames (at default threshold): transitions to HOLDING state
    - Dropout counter resets to 0 when detection returns

    ## Hold Behavior (DTCT-01)
    - When detection lost beyond dropout threshold: camera holds position, no motor commands sent
    - During hold: _flLowConfidenceTimer accumulates dt each frame
    - Hold duration configurable via existing flConfidenceLowTimeoutSeconds (default 5.0s)
    - MotionProfiler.reset() called on entering HOLDING to prevent stale velocity on recovery
    - _dPreviousControlTimestampSeconds NOT updated during hold (handled on recovery)

    ## Home Return After Timeout (DTCT-02)
    - After hold timer exceeds flConfidenceLowTimeoutSeconds: feeds HomeReturnController with angle 0.0
    - HomeReturnController transitions through SAFE_ZONE_DELAY -> RETURNING_HOME -> AT_HOME
    - Uses existing _send_profiled_motor_command for the return motion (same S-curve as MOTN-02)
    - DetectionState transitions from HOLDING to RETURNING_HOME

    ## Recovery Easing
    - Detection recovered from HOLDING: set _dRecoveryStartTimestamp, reset low-confidence timer, set _dPreviousControlTimestampSeconds = now (prevents dt gap)
    - Detection recovered from RETURNING_HOME: additionally reset HomeReturnController and reset OneEuroFilter (state too stale)
    - Recovery ramp: smoothstep from 0.0 to 1.0 over flRecoveryEasingDurationSeconds (default 0.4s), multiplied into flConfidenceScale
    - After ramp completes: _dRecoveryStartTimestamp set to None

    ## Config Fields
    - iDetectionDropoutFrameThreshold: int = 3 (frames before declaring detection lost)
    - flRecoveryEasingDurationSeconds: float = 0.4 (ramp duration on recovery)
  </behavior>
