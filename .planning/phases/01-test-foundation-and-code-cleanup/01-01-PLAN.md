  <name>Task 1: Create SimulatedMotorInterface with trapezoidal motion physics</name>
  <files>src/interfaces/motor_interface.py</files>
  <action>
Add a new `SimulatedMotorInterface` class in motor_interface.py (below the existing `NullMotorInterface`). This replaces NullMotorInterface for all testing scenarios.

The class must:
1. Implement the SAME public API as MotorInterface and NullMotorInterface: `connect_to_motor_controller()`, `disconnect_from_motor_controller()`, `is_connected_to_motor_controller()`, `send_move_to_angle_command()`, `send_emergency_stop_command()`, `send_home_command()`, `send_enable_driver_command()`, `send_speed_and_acceleration_settings()`, `send_reset_position_command()`, `get_latest_motor_state()`, `get_estimated_motor_angle_degrees()`, `set_feedback_callback()`.

2. Use trapezoidal velocity profile physics in `advance_simulation(dDeltaTimeSeconds: float)`:
   - Compute distance to target
   - Compute stopping distance: v^2 / (2*a)
   - If stopping distance >= remaining distance: decelerate
   - Else if below max speed: accelerate
   - Else: cruise at max speed
   - Update position: angle += velocity * dt
   - Near target (abs(distance) < 0.001 and abs(velocity) < 0.01): snap to target, zero velocity

3. Instance variables (use Hungarian notation):
   - `_flCurrentAngleDegrees = 0.0`
   - `_flTargetAngleDegrees = 0.0`
   - `_flCurrentVelocityDegreesPerSecond = 0.0`
   - `_flMaxSpeedDegreesPerSecond = 30.0`
   - `_flAccelerationDegreesPerSecondSquared = 60.0`
   - `_dLastUpdateTimestampSeconds = time.perf_counter()`
   - `_obStateLock = threading.Lock()`
   - `_obMotorStateHistory = deque(maxlen=100)`
   - `_iSequenceNumber = 0`
   - `_bBackgroundThreadRunning = False`
   - `_obBackgroundThread = None`
   - `_fnFeedbackCallback = None`

4. `send_move_to_angle_command(flTargetAngleDegrees)` sets `_flTargetAngleDegrees` under lock. Returns True.

5. `send_speed_and_acceleration_settings(flMaxSpeedStepsPerSecond, flMaxAccelerationStepsPerSecondSquared)` converts steps/s to degrees/s using the gear ratio constant: `flDegreesPerStep = 360.0 / 288000.0` (200 steps * 180:1 gear * 8 microstep = 288,000 steps/rev). Store the converted values.

6. `get_latest_motor_state()` returns a MotorState copy under lock with current angle, target, velocity (converted to steps/s), bMotorIsMoving = abs(velocity) > 0.01 or abs(distance_to_target) > 0.001, timestamp from last update.

7. `get_estimated_motor_angle_degrees(dAtTimestampSeconds)` interpolates from `_obMotorStateHistory` (same logic as MotorInterface).

8. `start_background_simulation()` and `stop_background_simulation()` methods: create/stop a daemon thread that calls `advance_simulation()` at ~1000 Hz (1ms intervals) using `time.perf_counter()` for delta calculation. This is for interactive `main.py --video` mode only. Tests call `advance_simulation()` directly with explicit time steps.

9. `send_home_command()` sets target to 0.0. `send_emergency_stop_command()` sets target to current angle and velocity to 0. `send_reset_position_command()` sets current angle, target, and velocity all to 0.

Do NOT modify the existing NullMotorInterface class -- keep it for backward compatibility. Do NOT modify the existing MotorInterface class.

Keep the existing `NullMotorInterface` intact. Add imports for `threading`, `deque` at module top if not already present (they are).
  </action>

  <name>Task 2: Extend CameraInterface for video file input with looping</name>
  <files>src/interfaces/camera_interface.py, src/main.py</files>
  <action>
**camera_interface.py changes:**

1. Add `sVideoFilePath: str = ""` parameter to `__init__()` (after `iCameraFramesPerSecond`). Store as `self.sVideoFilePath`.

2. Modify `open_camera_device()`:
   - If `self.sVideoFilePath` is non-empty, use `cv2.VideoCapture(self.sVideoFilePath)` instead of `cv2.VideoCapture(self.iCameraDeviceIndex)`.
   - When opening a video file, do NOT set CAP_PROP_FRAME_WIDTH, CAP_PROP_FRAME_HEIGHT, CAP_PROP_FPS, or CAP_PROP_AUTOFOCUS (these are camera-only properties that are either ignored or cause issues with file sources).
   - Instead, READ the actual dimensions from the file: `iActualWidth = int(self.obVideoCapture.get(cv2.CAP_PROP_FRAME_WIDTH))` etc.
   - Log differently: "Video file opened: {path} ({width}x{height} @ {fps} FPS)" vs the existing camera log.

3. Modify `capture_frame_with_timestamp()`:
   - After `bSuccess, obFrame = self.obVideoCapture.read()`, if `not bSuccess and self.sVideoFilePath`:
     - Call `self.obVideoCapture.set(cv2.CAP_PROP_POS_FRAMES, 0)` to loop the video
     - Retry: `bSuccess, obFrame = self.obVideoCapture.read()`
     - Update timestamp: `dTimestampSeconds = time.perf_counter()`
   - This provides automatic looping for video files. Camera sources still fail normally (no looping for cameras).

**main.py changes:**

1. Add `--video` argument to `setup_argument_parser()`:
   ```python

   )
   ```

2. In `initialize_system(obConfig)`, accept an optional `sVideoFilePath=""` parameter. When `sVideoFilePath` is non-empty:
   - Pass it to `CameraInterface(sVideoFilePath=sVideoFilePath, ...)`
   - Also force `SimulatedMotorInterface` instead of trying real motor connection (synthetic mode = no hardware at all)

3. In `main()`, pass `obArgs.video` to `initialize_system()`:
   - Change the call signature: `initialize_system(obConfig, sVideoFilePath=obArgs.video)`
   - When `--video` is used, also force `bAllowStartWithoutMotor` behavior (use SimulatedMotorInterface with background thread running)

4. Update the `initialize_system` function: When using `--video` mode, replace `NullMotorInterface` with `SimulatedMotorInterface` and call `start_background_simulation()` on it. Import `SimulatedMotorInterface` alongside the existing imports.

5. Update the import line at the top of main.py to include SimulatedMotorInterface:
   `from interfaces.motor_interface import MotorInterface, NullMotorInterface, SimulatedMotorInterface`
