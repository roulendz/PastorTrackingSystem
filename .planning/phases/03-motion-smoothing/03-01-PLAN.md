**Module 1: `src/tracking/pose_filter.py` -- OneEuroFilter (MOTN-03)**

Implement the OneEuroFilter for pose jitter suppression. This is a hand-rolled implementation from the reference algorithm (Casiez et al., CHI 2012) -- no external dependency.

Classes and functions:
- Module-level `_compute_smoothing_factor(flTimeDelta: float, flCutoffHz: float) -> float` -- computes exponential smoothing alpha from time delta and cutoff frequency: `r = 2*pi*cutoff*dt; return r/(r+1)`
- Module-level `_apply_exponential_smoothing(flAlpha: float, flRaw: float, flPrevious: float) -> float` -- standard EMA: `alpha*raw + (1-alpha)*previous`
- `class OneEuroFilter` with:
  - `__init__(self, dInitialTimestamp: float, flInitialValue: float, flMinCutoffHz: float = 1.0, flBeta: float = 0.007, flDerivativeCutoffHz: float = 1.0)`
  - State: `_flMinCutoffHz`, `_flBeta`, `_flDerivativeCutoffHz`, `_flPreviousRaw`, `_flPreviousFiltered`, `_flPreviousDerivative`, `_dPreviousTimestamp`
  - `filter_value(self, dTimestamp: float, flRawValue: float) -> float` -- filter one raw value, return smoothed result. If dt <= 0, return previous filtered value. Otherwise: estimate derivative, smooth derivative, compute adaptive cutoff = minCutoff + beta*abs(smoothedDerivative), smooth raw value with adaptive cutoff, update all state, return filtered value.
  - `reset(self, dTimestamp: float, flValue: float)` -- reinitialize all state (for when tracking restarts fresh)
  - Parameters `_flMinCutoffHz` and `_flBeta` should be directly settable attributes (no lock needed -- CPython GIL makes float assignment atomic, same pattern as existing config attribute updates)
- Module-level `compute_confidence_scale_factor(flConfidence: float, flHoldThreshold: float = 0.3, flFullThreshold: float = 0.7) -> float` (MOTN-04) -- returns 0.0 below hold, 1.0 above full, cubic smoothstep between: `t*t*(3-2*t)`

Default OneEuroFilter parameters (per research):
- `flMinCutoffHz = 1.0` -- aggressive smoothing when stationary
- `flBeta = 0.007` -- responsive at walking speed
- `flDerivativeCutoffHz = 1.0` -- standard derivative smoothing

**Module 2: `src/control/motion_profiler.py` -- MotionProfiler (MOTN-01)**

Implement a velocity-domain S-curve profiler. This is NOT a full trajectory planner -- it rate-limits velocity changes with exponential approach that produces S-curve-like acceleration. Per research: "The velocity-domain approach is simpler and adequate for camera panning."

Class:
- `class MotionProfiler` with:
  - `__init__(self, flMaxVelocityDegreesPerSecond: float = 30.0, flAccelerationTimeSeconds: float = 0.4, flDecelerationTimeSeconds: float = 0.5)`
  - State: `_flCurrentVelocity: float = 0.0`
  - `compute_smoothed_velocity(self, flDesiredVelocity: float, flDeltaTimeSeconds: float) -> float` -- apply S-curve smoothing to transition from current velocity toward desired velocity:
    1. Compute delta = desired - current. If abs(delta) < 0.001 deg/s, return current (dead zone to prevent oscillation).
    2. Determine if decelerating: abs(desired) < abs(current) OR sign change (desired and current have opposite signs).
    3. Select time constant: decel time if decelerating, accel time otherwise.
    4. Compute alpha = 1.0 - exp(-dt / (timeConstant * 0.2)) (exponential approach).
    5. Update: current += alpha * delta. Store and return.
  - `reset(self)` -- set `_flCurrentVelocity = 0.0`
  - `get_current_velocity(self) -> float` -- return `_flCurrentVelocity`
  - Parameters `_flAccelerationTimeSeconds` and `_flDecelerationTimeSeconds` should be directly settable as `flAccelerationTimeSeconds` and `flDecelerationTimeSeconds` public attributes for runtime tuning.

Key behavior: Direction reversals are handled naturally -- when desired velocity flips sign, the profiler decelerates through zero (using decel time constant) then accelerates in the new direction. No special-case code. Per CONTEXT.md: "smooth decel through zero, brief pause, smooth accel in new direction."

**Module 3: `src/control/home_return_controller.py` -- HomeReturnController (MOTN-02)**

Implement the home return state machine. Uses a MotionProfiler instance internally for S-curve return motion.

Enum:
- `class HomeReturnState(Enum): TRACKING, SAFE_ZONE_DELAY, RETURNING_HOME, AT_HOME`

Class:
- `class HomeReturnController` with:
  - `__init__(self, flDelaySeconds: float = 1.5, flReturnMaxVelocity: float = 10.0, flReturnAccelTime: float = 0.5, flReturnDecelTime: float = 0.5, flReengagementAccelTime: float = 0.3)`
  - State: `_eState: HomeReturnState = HomeReturnState.TRACKING`, `_flDelayTimer: float = 0.0`, `_obReturnProfiler: MotionProfiler` (internal profiler for return motion), `_flReturnTargetAngle: float = 0.0` (tracks S-curve interpolated position during return)
  - `update(self, flPersonAngleRelativeToHome: float, flSafeZoneThresholdDegrees: float, flDeltaTimeSeconds: float, flCurrentMotorAngleDegrees: float) -> HomeReturnState`:
    - Determines whether person is in safe zone: `abs(flPersonAngleRelativeToHome) <= flSafeZoneThresholdDegrees`
    - State transitions per CONTEXT.md decisions:
      - `TRACKING -> SAFE_ZONE_DELAY`: person enters safe zone, start delay timer
      - `SAFE_ZONE_DELAY -> RETURNING_HOME`: timer expires (>= flDelaySeconds)
      - `SAFE_ZONE_DELAY -> TRACKING`: person leaves safe zone before timer expires
      - `RETURNING_HOME -> TRACKING`: person leaves safe zone during return (CRITICAL: do NOT reset the motion profiler -- let its velocity state carry over for smooth transition. Per research Pitfall 3.)
      - `RETURNING_HOME -> AT_HOME`: motor close enough to 0.0 (within 0.01 deg) AND profiler velocity near zero
      - `AT_HOME -> TRACKING`: person leaves safe zone (use faster re-engagement accel time per CONTEXT.md)
    - Returns the current state after update.
  - `get_target_angle(self) -> float` -- when RETURNING_HOME, returns the S-curve-profiled target angle (gradually approaching 0.0). When AT_HOME, returns 0.0.
  - `get_state(self) -> HomeReturnState` -- return current state
  - `reset(self)` -- back to TRACKING state, reset timer and profiler
  - Delay `flDelaySeconds` should be a public attribute for runtime tuning.

  When RETURNING_HOME:
  - Compute desired velocity toward home: direction = sign(0.0 - currentAngle), magnitude = returnMaxVelocity
  - Pass through internal MotionProfiler for S-curve shaping
  - Integrate: _flReturnTargetAngle += smoothedVelocity * dt
  - Clamp return target so it does not overshoot past 0.0 (zero overshoot per CONTEXT.md)

  When transitioning from AT_HOME -> TRACKING:
  - Set the internal profiler's acceleration time to flReengagementAccelTime (faster re-engagement per CONTEXT.md "slightly faster S-curve re-engagement when leaving home")
  - After the first update in TRACKING state, restore normal acceleration time
